# 谁算她：认人判据

这一页回答一件事：**DSH 里这么多会话，哪一条算大肥鱼，哪一条只是他开的普通会话。**

结论先给：**认会话 id，不认工作目录。** 工作目录只用来决定「这条 id 不在册的会话，要不要等一封外面来的信」。

这份判据在 1.0.8 定下、1.0.9 补齐桥的来路。1.0.6 及更早按目录认人，把他开在她屋子里的会话也收窄成了「这件事我做不了」；1.0.8 改成按 id。桥自建会话第一次被接住是 1.0.9 的事。

---

## 一、两条判据，各管一件事

| 判据 | 回答的问题 | 用在哪 |
| --- | --- | --- |
| `isHerAgent(agent, herDir)`（`isHerHome`） | 这条会话**是不是她** | 身份段挂不挂、工具面收不收窄 |
| `isHerAnywhere(agent, herDir, extraDirs)` | 是不是**她这个人**（含出门） | 只决定身份段挂不挂 |

出门那一路不在家里：工具面**不收窄**（外面按那个工作区的权限走），但身份段仍然挂——否则她在外面会失去全部来历。请神不走这两条，身份由请神那套单独挂。

`sidKey()` 会抹掉会话 id 的 `session-` 前缀，两种写法都认。

写入口（`lib/tenant.js` 的 `guardWrite`）也是这一套：会话 id 在册就放行，**cwd 在哪都不影响**；不在册才拿**当前**工作目录（宿主的 `workingDirectory.get(session)`，取不到回落出生目录）和 root / herDir 比。1.0.9 只看出生目录，会话换过 `working_directory` 之后所有写入口会一起判成「另一个家」（issue #179）。

## 二、会被认作她、并挂身份段的

### 1. 插件自己建的会话

| 来路 | 怎么进台账 |
| --- | --- |
| 首次开档 / 轮换 / 换房（`lib/home.js` 的 `createTalkSession`） | 建会话时 `asHerSession(herDir, …)` 开认领窗口，宿主的 `agent/created` 当场认；返回后 `rememberHerSession(id)` 补一笔 |
| 群房 / 外客（`lib/say.js`） | 同上 |
| 认回旧窗口（`adoptTalkSession`） | 认回时立刻记 id |

`asHerSession` 的窗口只在 `await sc.create()` 那一下开着，并且要求会话 cwd 等于她的家。开大了会把她屋里他随手开的会话也吞进来——那正是 1.0.6 的毛病。

### 2. 重启后读回的老会话

`seedHerSessions(root)` 从两份台账读：

- `home.json` 的 `sessionId` / `rotatedFrom` / `rotatedTo` / `pressureRoomIds`；
- `channels.json` 每间房的 `sessionId`。

读坏了当没读到，不抛；一个数据目录只读一次。

### 3. 桥自建的会话（1.0.9）

桥不在这条建会话的路上：它自己起一条 DSH 会话，再把 QQ / Telegram 的话 prompt 进来。这条会话 cwd 是她的家，id 却不在册。

处理分三步：

1. **建会话时**：`isHerAgent` 为假 → 不挂身份、不收窄，只登记一个待认领回调（`lib/claim.js` 的 `whenHers`）。
2. **第一封外面来的信到达**：`lib/turns.js` 的 `classifyMessage` 判来源，`isBridgeMessage` 判是不是桥，命中就 `claimSession(id, herDir)`。
3. **认领后补挂**：`lib/identity.js` 补 `attachIdentity`，`lib/restrict.js` 重跑一遍装备（记 id、下白名单、挂守卫）。

「外面来的信」必须三条同时满足：

- 会话 cwd 就是 `~/.dsh-fish/home`（路径归一后比较）；
- 会话 id 不在这个家的台账里；
- 来信属于下面三种之一：
  - **桥显式声明**：`source.bridge === true`（1.1.1 新增契约，只有插件投递才写得出来）；
  - **插件中转**：`source.kind` 是 `plugin:<插件名>`（`dsh-onebot-qq` 这类直接 `followup` 的桥，不经过宿主 `prompt()`），自己插件的 `plugin:dsh-fish` 与带 `fish` 标记的不算；
  - **宿主 `prompt()` 送进来的**：`kind === 'user'`，并且满足其一——`source.scene === 'group'`（群聊，或群里的他）、`source.guest === true`（外客）、`classifyMessage` 判成 `human` 且**没有** `clientTimeZone`。

`kind === 'user'` 仍是 `prompt()` 这一路（第三条）的硬门槛（1.0.9 对抗复核补的）：宿主 `prompt()` 在正文为空时把 kind 写成 `retry`，`classifyMessage` 的兜底又会把不认识的 kind 当成人。他屋里那条普通会话点一次「重试」，就长得和桥来信一样——1.0.8 修掉的误伤会从这道门回来。

「插件中转」这条是 1.1.1 补的（2026-11-24 外部报告）：QQ 私聊桥把消息直接 `followup` 进会话，`kind` 写自己的 `plugin:dsh-onebot`，永远等不到一条 `kind:'user'` 的信——每换一次房、每重启一次就掉一次人设。取舍：别的插件往一条「建在她屋里、还没认领」的会话里投消息，也会触发认领；这比私聊新会话全部裸跑轻得多。桥若能写 `bridge: true`，优先用那条。

### 3.1 桥不建在她的家里：`bridge.dirs` 与 `/claim`（1.1.1）

市面上的桥大多不把会话建在 `~/.dsh-fish/home`，而是自己挑一个工作目录。1.1.1 给两条入口，默认都关着：

- **`bridge.dirs`**（`config.json` 里，不在设置页）：列桥建会话的目录。会话 cwd 落在其中任意一个下面、且收到第一封桥来信时，走第 3 节同样的三步认领。目录按「反斜杠转正、去尾斜杠、小写」比较，最多 20 条。它只放宽「建在哪儿」，来信判据一条没松。
- **`POST /claim`**（`bridge.claim: true` 才开）：桥显式点名一条会话，不用等第一封信。请求体 `{ "sessionId": "session-…" }`，头里带 `x-fish-token`（就是 `config.bridge.token`）。它只在**会话创建后 10 分钟内**接受，并且那个 agent 得还在内存里；响应 `ok / already / not_live / too_old / not_waiting / unknown_session / refused`。认领同时挂身份段与收窄工具面，不留「半挂」。
- **`POST /release`**：撤销认领，把 id 从台账里摘掉、摘身份段；工具面收不回来，要连工具面一起恢复得重开会话。它不会自动触发——他本人在那条会话里打字也照样是「她」，因为本地字与桥来信在同一条会话里无法可靠分开；要收回就由桥或人显式调一次。

安全边界：`/claim`、`/release` 挂在同一个本机投递口上，除原有的绑 `127.0.0.1`、Host 校验、拒浏览器之外，还要求 token（`timingSafeEqual`）与 20 KB 请求体上限；默认 `bridge.claim: false`，不主动开就完全不存在。认领记录落在 `bridge.json`，最多留 500 条，坏档当空。

### 3.2 记账侧：谁算「他来过」（1.1.2，issue #180）

认成她，和算「他来过」，是两条判据，分别落在 `isBridgeMessage()` 与 `classifyMessage()`。1.1.2 之前后者把 `plugin:` 前缀一律判成 `context`，于是 `dsh-onebot-qq` 用 `followup` + `kind:'plugin:dsh-onebot'` 投进来的话，身份段挂上了、她照常回，但 `seen:` / 轮数 / `heard` 全断——冷落钟一直涨。

这一版只开两道很窄的口：

- **`source.bridge === true`**：桥显式声明，`classifyMessage()` 直接判 `human`；`kind` 是 `retry` 或空时仍判 `context`。
- **同 kind 认领**：认领时把 `source.kind` 记进 `bridge.json` 的 `via`（显式 `/claim` 没有 kind，`via` 留空 = 不限 kind）。之后只有**同一个 kind** 在那条会话里算 `human`；同一条会话里别的插件投的消息照旧 `context`。插件重启后从 `bridge.json` 灌回。

为什么不对所有 `plugin:` 放开：同一条她会话里还有别的插件投消息（叫醒、补丁、别的工具），按「会话是桥的」一概算人，就会把那些也算成他来过，并破掉 `plugin:hindsight` / `plugin:whatever` 仍是 `context` 的边界。

老会话迁移：1.1.2 之前认领的桥会话没有 `via`，桥补 `source.bridge: true`（立即生效），或重新 `/claim` / 新开会话即可。

### 4. 出门

`outing.json` 里 active 那一条，三种情况认：

- 台账已经记了 `sessionId`，并且和这条会话对上了；
- 台账还没绑 id，而这条会话的 cwd 就是出门那个工作区；
- 台账刚写、`sessionId` 还空着，会话也还没 cwd（`start` 路由「先记账再建会话」）。

两边都有 id 却不相等 → 不是她。第二种只在「台账还没绑 id」时生效；一旦绑上，同一个工作区里他开别的会话不会被挂身份（2026-10-29 真机踩过：连自己的记忆文件都读不了）。

## 三、不会被认的

- **他自己开在她屋里的普通会话**：本地客户端打的字一定带 `clientTimeZone`，永远等不到那封信 → 不挂身份、不收窄。
- **任何不在她屋里的会话**：插件在跑也与他自己的工作区无关；别的鱼的家也互不相认（台账按 `herDir` 分域）。
- **桥走 `/say` 或复用已有 `sessionId`**：根本不建新会话，不需要认领，也不受影响。
- **桥把会话建在别的工作区**：连待认领回调都不会登记，来信也不认领。
- **插件自己发的消息**（`source.fish === 'note'`、`rpcId` 以 `PLUGIN_RPC` 开头）和**宿主上下文**（没有 `source`）：不算信。
- **自起 kind 的来信**（比如 `kind:'qq'`）：不算。桥经宿主 `prompt()` 时宿主固定写 `user`。
- **重试 / 空正文 prompt**（`kind:'retry'`）：不算，见上。

## 四、两个不对称与已知边界

1. **老宿主拿不到会话 id 时**：`isHerAgent` 退回 cwd 比较，所以**会**收窄；但 `lib/identity.js` 的待认领分支要求有 id，**没有 cwd 兜底** → 身份段永远不挂。新宿主都会给 id，碰不到这一条。
2. **插件热重载**：插件启动前 agent 已经存在时，不会再有 `agent/created`，也就没有待认领回调 → 桥来信也认不了。整机重启不受影响。
3. **cwd 要写对**：桥建会话时 cwd 必须是 `~/.dsh-fish/home` 本身。换一个路径写法、或落到联接（junction）外面，登记条件就不成立。

## 五、怎么当场确认一条会话是不是她

看 `dsh-fish.log`：

- 挂上了：`身份段已挂进 system prompt（第 N 次）`；桥会话会多一句 `身份段已挂进 system prompt（第 N 次·桥的会话）`。
- 没挂：`身份段没挂上：<原因>`；或 `有条出门记录，但这条会话没对上：cwd=… sid=…`。
- 收窄：守卫日志带 `session=<id>`；她被挡时是「这件事我做不了」——他自己的会话不会出现这句。

## 六、代码位置

| 文件 | 管什么 |
| --- | --- |
| `lib/restrict.js` | 台账 `herSessions`、`asHerSession`、`rememberHerSession`、`seedHerSessions`、`isHerAgent` / `isHerAnywhere`、装备与守卫 |
| `lib/identity.js` | `registerIdentity`：身份段挂载、出门识别、桥会话等信 |
| `lib/claim.js` | 待认领回调、`claimSession`、`isBridgeMessage` |
| `lib/turns.js` | `classifyMessage`、`session/event` 里触发认领 |
| `lib/home.js` / `lib/say.js` | 建会话时开认领窗口并记 id |

## 七、改这一块时先想清楚的三件事

1. **不要退回「按 cwd 认人」**：那会把用户自己的会话再收窄一次，1.0.6 的外部报告就是这样来的。
2. **不要放宽 `isBridgeMessage` 的 `kind`**：放宽一次，重试后门就回来了。
3. **认领是补挂，不是重开**：认领后 `attachIdentity` 是惰性读，同一轮能生效；工具面在装备那一刻同步下发，最多晚一轮。
